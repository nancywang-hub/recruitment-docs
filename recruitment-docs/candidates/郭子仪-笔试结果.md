# AI 本地大脑（AI Local Brain）原型：企业多源数据 × 最小 RAG × 角色化驾驶舱

本仓库交付物是一个**可演示的 Streamlit Demo 应用**：把企业多源数据（聊天 + CRM）整合为本地知识库（JSONL 索引），提供**两角色（销售总监/HR）**的驾驶舱体验，覆盖题目三大模块：

- **摘要（Summary）**：基于检索片段输出 3–5 条要点，并带引用编号 [1][2]
- **趋势洞察（Trends & Insights）**：按角色展示图表，并生成 2–3 句 AI 洞察（每句 ≤80 字）
- **问答（Q&A）**：TopK 检索 + 角色化回答 + 引用片段展示

> 备注：仓库还保留了 `app.py` 的“多专家路由系统”调试台作为辅助演示/对比能力，但题目主交付以 `cockpit.py` 为准。

## 🚀 快速开始

### 环境要求
- Python 3.10 或 3.11（推荐 3.11；Windows 下 Python 3.14 可能因 numpy/torch 轮子缺失导致安装失败）
- SiliconFlow API Key（OpenAI 兼容接口）

### 安装步骤

1. **创建虚拟环境**
```powershell
cd H:\agent
python -m venv .venv
```

2. **激活虚拟环境**
```powershell
.\.venv\Scripts\Activate.ps1
```

3. **安装依赖**
```powershell
pip install -r requirements.txt
```

4. **设置 API Key**
```powershell
$env:OPENAI_API_KEY="你的SiliconFlow API密钥"
```

> 可选（本地开发）：项目已集成 `python-dotenv`，会在启动时尝试加载同目录的 `.env`。仓库提供 `.env.example` 作为模板，请**仅在本地**复制为 `.env` 使用，切勿提交真实 `.env`。

5. **启动应用**
```powershell
streamlit run app.py
```

浏览器将自动打开 `http://localhost:8501`

### 启动驾驶舱（含最小 RAG）

```powershell
streamlit run cockpit.py
```

- 首次使用建议先点击 **“构建索引”**（会在本地生成 `rag_store/index.jsonl` 与 `rag_store/meta.json`）
- 再点击 **“检索并回答”** 进行角色化问答
- 默认提供方（交付口径）：**SiliconFlow OpenAI 兼容接口**（目标状态）
- 现状提示：当前工程师实现尚未把代码内默认值全部切到 SiliconFlow，建议按下方“最小执行清单”显式设置 env 以确保可跑通
- 推荐默认 embedding 模型名示例：`BAAI/bge-large-zh-v1.5` 或 `BAAI/bge-m3`（以 SiliconFlow 控制台可用为准）
- chat 模型名需要从 SiliconFlow 控制台选择（请填你账号可用的 chat 模型名）

## 🎯 项目目标与范围（对齐题目三大模块）

- **目标**：用最小代价搭建"AI 本地大脑"原型，把多源企业数据汇聚为可检索的知识库，并在角色化驾驶舱中输出摘要、趋势洞察与问答。
- **范围（已覆盖）**：
  - **数据源**：飞书群聊（CSV）+ CRM 商机（Excel）
  - **知识库**：本地 `rag_store/index.jsonl`（chunks + embeddings + metadata）
  - **RAG**：远程 embeddings + 本地暴力 cosine TopK + 引用输出
  - **驾驶舱**：两角色视角 + 摘要/图表/问答 + 一键洞察
- **不在范围（原型取舍）**：SOTA 向量库、复杂权限/审计、实时数据接入、生产级可观测性

## 💡 设计思路与项目演进

本项目采用**渐进式迭代设计**，从最初的专家智能路由系统原型逐步演进为完整的 RAG 驾驶舱应用。以下是关键演进阶段：

### 阶段 1：专家智能路由系统（2025-12-16）

**初始原型**：`app.py` - 多专家路由 Demo
- **设计目标**：验证 OpenAI 兼容接口调用能力，探索智能路由的可能性
- **核心功能**：
  - Streamlit 双栏对比界面（左侧手动 Prompt，右侧自动路由）
  - 专家库：Python 架构师、诗人、战略顾问
  - 基于意图识别自动匹配专家角色
- **技术验证**：环境变量管理、OpenAI SDK 集成、Streamlit UI 基础

> **保留价值**：`app.py` 作为辅助演示/对比能力保留在仓库中，展示从"通用对话"到"角色化问答"的演进路径。

### 阶段 2：基础设施与数据准备（2025-12-17）

**环境修复**（`fix_environment`）：
- 创建 `requirements.txt` 依赖清单
- 移除硬编码 API Key，强制使用环境变量
- 建立安全配置基础

**Mock 数据生成**（`mock_data_generator`）：
- 生成 `data/feishu_chat.csv`（50 条群聊消息，包含 3 个关键主题）
- 生成 `data/crm_opportunities.xlsx`（100 条商机数据）
- 为后续 RAG 管线提供数据基础

**驾驶舱 UI 骨架**（`cockpit_layout_scaffold`）：
- 创建 `cockpit.py`，搭建角色化 UI 框架
- 左侧 Sidebar 角色选择（销售总监/HR）
- 为后续功能集成预留接口

### 阶段 3：RAG 知识库构建（2025-12-18）

**最小 RAG 管线**（`rag_minimal_pipeline`）：
- **设计决策**：采用"远程 embedding + 本地 JSONL + 标准库 cosine 检索"
  - **原因**：规避 Windows + Python 3.14 环境下 torch/numpy 轮子兼容性问题
  - **权衡**：牺牲性能换取"可安装/可演示"的稳定性
- **实现**：`rag_pipeline.py`
  - 数据加载与分片（CSV/Excel → chunks）
  - 远程 embedding（SiliconFlow API）
  - 本地 JSONL 索引存储
  - 标准库 cosine 相似度 TopK 检索
  - 角色化回答生成（带引用编号）

**驾驶舱集成**：
- `cockpit.py` 接入 RAG 管线
- 提供"构建索引"和"检索并回答"功能
- 展示引用片段与相似度

### 阶段 4：AI 洞察与可视化（2025-12-18）

**AI 摘要与洞察模块**（`cockpit_ai_insights`）：
- **摘要生成**：基于检索片段生成 3-5 条角色化要点，带引用编号 [1][2]
- **趋势图表**：
  - 销售总监：Amount 月度趋势、Stage 占比、Top Owner
  - HR：聊天关键词热度（代理指标）、Stage 分布（HR 意义解释）
- **AI 洞察**：基于图表数据生成 2-3 句洞察文本（每句 ≤80 字）

**设计理念**：从"问答"扩展到"摘要+图表+洞察"，形成完整的决策支持闭环。

### 阶段 5：配置优化与健壮性增强（2025-12-19）

**单提供方模式**（`provider_switch_siliconflow_single`）：
- **问题**：DeepSeek embeddings 不可用导致"构建索引失败"
- **解决方案**：统一切换为 SiliconFlow 单提供方（Embedding + Chat）
- **效果**：从根源上解决模型兼容性问题，降低配置复杂度

**错误处理增强**：
- 模型不存在错误提示优化
- 防呆检查：避免误将 embedding 模型填到 CHAT_MODEL
- 三个入口（检索并回答/生成摘要/生成洞察）均具备防呆能力

**环境变量管理**（`security_env_setup`）：
- 集成 `python-dotenv` 支持 `.env` 文件
- 启动时强制校验 API Key
- 提供 `.env.example` 模板

### 阶段 6：云端部署能力（2025-12-19）

**FastGPT 云端部署**（`fastgpt_devops_deployment`）：

- 为后续 FastGPT API 集成奠定基础

### 设计原则总结

1. **渐进式迭代**：从简单原型（专家路由）逐步扩展功能（RAG、洞察、部署）
2. **最小可行架构**：优先选择"可安装/可演示"的稳定方案，而非追求 SOTA 性能
3. **向后兼容**：保留 `app.py` 作为对比能力，展示演进路径
4. **健壮性优先**：通过配置优化和错误处理，确保 Demo 可稳定运行
5. **一次一个功能**：每个阶段聚焦单一目标，保持代码清晰可读

## 🧩 数据源与模拟方案

## 🏗️ 知识库 / RAG 架构（默认方案）

- **索引产物**：
  - `rag_store/index.jsonl`：每行一个 chunk，包含 `text/source/...` 与 embedding 向量
  - `rag_store/meta.json`：索引构建元信息
- **检索策略**：
  - 远程 embeddings（OpenAI SDK 兼容接口）
  - 本地标准库 cosine similarity 做 TopK（避免 torch/numpy 依赖坑）
  - `query()` 返回：`{"answer": str, "sources": [{"rank","source","score","content"}, ...]}`
- **引用规则**：
  - LLM 输出要点/回答时必须在句末附 `[1][2]`，对应 sources 的 rank

## 👤 角色设计（销售总监 / HR）

- **销售总监关注点**：营收趋势、阶段进展、客户投诉、竞品价格战、下一步行动
- **HR 关注点**：团队压力信号、绩效风险、支持/培训建议（允许使用“代理指标”图表）

## 🚀 部署指南（Deployment Guide）

### 本地部署（推荐用于开发/演示）

**环境要求**：

3. **配置环境变量**：创建 `.env` 文件并填写 API Key（参考"一键启动"章节）

**验证部署**：
- 点击"构建索引"应能成功生成 `rag_store/index.jsonl`
- 点击"检索并回答"应能返回答案和引用片段
- 切换角色应能看到不同的摘要和图表

### 云端部署（FastGPT 服务）

**部署目标**：在阿里云 ECS 服务器上部署 FastGPT 全家桶，为后续 FastGPT API 集成提供云端服务。

**部署环境**：
- **服务器**：阿里云 ECS（Ubuntu 22.04）
- **配置**：2vCPU / 8GB RAM / 40GB Disk（最低配置）
- **网络**：开放端口 3000（FastGPT）、5432（PostgreSQL）、27017（MongoDB）、6379（Redis）

**部署架构**：
```
FastGPT 服务栈
├── FastGPT（主服务，端口 3000）
├── MongoDB（文档存储，端口 27017）
├── PostgreSQL + PgVector（向量存储，端口 5432）
├── OneAPI（API 网关，端口 3001）
└── Redis（缓存，端口 6379）
```

## ⚖️ 权衡与限制（Trade-offs & Limitations）

- **远程 embeddings 的必要性**：在 Windows + Python 3.14 场景下，torch/numpy 轮子兼容性风险高；默认采用远程 embeddings + 本地 JSONL + 标准库检索，换取“可安装/可演示”的稳定性。
- **暴力检索的局限**：数据量大时会变慢；本原型只面向小数据集 Demo（可后续替换为向量库）。
- **模型名兼容性**：不同提供方的 embedding/chat 模型名可能不同，需要通过环境变量切换。

## 🧯 Troubleshooting（含 embedding 切换 / TEMP/TMP）

- **必须设置 OPENAI_API_KEY**：未设置会导致构建索引/问答/摘要/洞察失败
- **使用 .env 但启动后仍报“OPENAI_API_KEY 未设置”**：
  - 检查 `.env` 文件是否在项目根目录（与 `cockpit.py` 同级）
  - 检查格式是否正确（每行 `KEY=value`，无引号，无多余空格）
  - 确认 `.env` 文件已保存（编辑器可能未自动保存）
- **模型名不可用（最常见）**：
  - 现象：点击“构建索引”/“检索并回答”提示 model 不存在或不可用
  - 处理：到 SiliconFlow 模型列表/控制台确认你账号可用的 embedding/chat 模型名，并更新 `EMBEDDING_MODEL`/`CHAT_MODEL`（或在 `.env` 中修改）
- **误将 embedding 模型填到 CHAT_MODEL**：
  - 现象：系统会在调用 API 前提前拦截，抛出 `RuntimeError` 并提示“配置错误：你把 embedding 模型填到 CHAT_MODEL 了”
  - 原因：将 embedding 模型（如 `BAAI/bge-m3`）误填到 `CHAT_MODEL` 环境变量
  - 处理：`CHAT_MODEL` 必须是可用于 `chat.completions` 的对话模型名（如 `deepseek-ai/DeepSeek-V3`），请到提供方控制台确认可用模型名并更新配置
  - 说明：系统已为“检索并回答/生成摘要/生成洞察”三个入口均添加防呆检查，会在 API 调用前提前拦截误配置，避免等到 API 调用失败
- **不要再尝试 DeepSeek embeddings**：默认交付不再依赖 DeepSeek embeddings，避免“构建索引失败”
- **检索空命中**：问题过泛/数据不足 → 换更具体的问题（例如“华兴科技投诉集中在哪些问题？”）
- **Windows pip/缓存异常**：检查 `TEMP/TMP` 目录可写（必要时将其指向可写目录）
