# 实战题01：面向 AIGC 的智能水印防护系统（原型）

本项目实现一个可运行的原型系统：
- **核心功能一**：结构化可见水印（Logo 分块 + 跨区域分布 + 优先放在高频纹理区域）
- **核心功能二**：注入“抗 AI 修复”的对抗性扰动（针对 **Stable Diffusion Inpainting** 做梯度优化），使得涂抹去水印后修复结果出现明显视觉崩坏

同时提供：
- 可执行脚本（CLI）
- 可演示 Web 前端（Gradio）
- 可复现的验证流程（项目内置 SD inpaint 攻击/验证脚本）

## 环境准备

建议使用 Windows + NVIDIA GPU（CUDA）。第一次运行会从 HuggingFace 下载模型 `runwayml/stable-diffusion-inpainting`。

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

可选：把模型缓存到项目目录（避免默认缓存到系统盘）：
```powershell
$env:HF_HOME = (Resolve-Path .\\hf-cache).Path
```

## 一键生成（脚本）

```powershell
python .\\protect.py --image path\\to\\input.jpg --logo path\\to\\logo.png --outdir outputs\\demo
```

默认参数为“稳模式”（优化可能需要几分钟，取决于 GPU/分辨率/步数）。产出文件位于 `outputs\\demo\\`：
- `baseline_corner.png`：传统边角水印（用于对照）
- `structured_visible.png`：结构化可见水印（核心功能一）
- `protected_final.png`：结构化可见水印 + 对抗性扰动（核心功能二最终产物）
- `comparison_grid.png`：对比拼图（README 截图建议用这个）
- `attack_baseline.png` / `attack_protected.png`：同一套 SD inpaint 参数下的去水印结果
- `structured_mask.png`：结构化水印区域 mask（白=水印覆盖）
- `attack_mask_*.png`：用于验证攻击的涂抹 mask（对白区域做 inpaint）
- `structured_meta.json` / `adversarial_meta.json`：复现用元数据

说明：
- 本项目会把输入缩放到 `--max-side`（默认 384，8GB 显存更稳）并保证宽高为 8 的倍数，以满足 SD inpainting 的输入约束。

## 设计说明

### 核心功能一：结构化可见水印

目标：让盗图者不得不大面积涂抹/遮盖，增加 inpainting “猜测背景并补全”的难度。

实现要点：
- **跨区域与分块**：把 Logo 分成 `K(4~8)` 个不规则碎片（随机 blob mask），分散到画面不同位置。
- **融入高频纹理**：对原图计算高频热力图（Sobel 梯度幅值），对落点做加权采样，优先选择发丝/褶皱/树叶/波光等纹理复杂处。

### 核心功能二：对抗性扰动（抗 SD inpaint 修复）

目标：当盗图者使用 **Stable Diffusion Inpainting**（涂抹 mask 后修复）时，修复区域生成结果出现明显崩坏（色块、断裂、怪异纹理等），使去水印结果不可用。

实现思路（PGD + EOT）：
- 以 `structured_visible` 为基图，优化一个人眼几乎不可察觉的扰动 `δ`（约束 `||δ||∞ <= ε`，默认 `ε=8/255`）。
- 每次迭代随机生成一个“盗图者涂抹 mask”（对结构化水印区域做随机膨胀），并对多个 prompt 做循环，提升对不同涂抹方式/提示词的鲁棒性（EOT）。
- 在每次迭代中运行一段 SD inpaint 前向（默认 20 steps），并在 mask 区域最大化修复结果与原始背景的差异（`MSE` + 少量高频能量项），再用 PGD 更新 `δ`。

对应代码：
- 结构化水印：`watermark.py`
- SD inpaint（可微前向）：`sd_inpaint.py`
- 对抗扰动优化：`adversarial.py`
- 一键脚本：`protect.py`
- 验证攻击脚本：`sd_attack.py`

## 取舍与限制

- 为了保证可运行与可复现，本原型默认把输入缩放到 `--max-side` 并固定 SD inpaint 模型为 `runwayml/stable-diffusion-inpainting`。
- “对抗性扰动”属于原型级实现：追求的是 **可复现地让 SD inpaint 失败**，而非追求 SOTA 的跨模型/跨平台鲁棒性；如需进一步提升，可在 `adversarial.py` 增加更强的 EOT（JPEG/resize/随机 seed/prompt 集合）与更长的优化。

## 进阶挑战（选做）：不可见溯源水印

提供一套可跑通的“嵌入/解码”脚本，用于把版权信息（JSON 字符串）嵌入到最终防护图中，并在经历 JPEG 压缩/尺寸缩放后仍可解码（要求不包含裁剪）。

### 方法概述

- 频域嵌入：对图像 **Y 通道**做 8x8 DCT，默认使用 **diff（系数对比）**：在同一块内选一对中频系数，通过“拉开差值并固定符号”写入比特；也支持 `qim`（量化索引调制）方法。
- 扩频：每个比特写入多个随机槽位（`chips_per_bit`），解码时投票/累加，提升鲁棒性。
- 纠错：Reed-Solomon（`rs_nsym` 冗余字节）+ CRC32，提升 JPEG 噪声/缩放插值带来的比特错误容错。

对应代码：
- `trace_watermark.py`（核心算法）
- `embed_trace.py`（嵌入脚本）
- `decode_trace.py`（读取脚本）

### 嵌入

```powershell
python .\\embed_trace.py `
  --image outputs\\portrait_demo\\protected_final.png `
  --out outputs\\portrait_demo\\protected_final_trace.png `
  --meta-out outputs\\portrait_demo\\trace_meta.json `
  --key \"MySecretKey\" `
  --message '{\"author\":\"YourName\",\"id\":\"12345\"}' `
  --method diff
```

### 解码（支持 JPEG/缩放后再解码）

```powershell
python .\\decode_trace.py --image outputs\\portrait_demo\\protected_final_trace.png --meta outputs\\portrait_demo\\trace_meta.json --key \"MySecretKey\"
```

如果图片被压成 JPEG 或被缩放（不裁剪），仍可尝试解码：
```powershell
python .\\decode_trace.py --image path\\to\\attacked.jpg --meta outputs\\portrait_demo\\trace_meta.json --key \"MySecretKey\"
```

参数建议：
- 更鲁棒：增大 `--chips`（例如 24/32）或 `--rs-nsym`（例如 48/64）
- 更隐蔽：减小 `--margin`（diff 方法）或 `--step`（qim 方法），但鲁棒性会下降
- 说明：在“缩放 + JPEG”同时发生时，更建议在嵌入前放大图像（`embed_trace.py --embed-max-side 768`）并提高冗余参数
